iPad app: no audio input, no microphone permission

22 Oct 2026 · v0.9.2 · PR #170

  • iPad app: no audio input, no microphone permission

    The synth never uses its audio input (processBlock() overwrites every sample). On iPadOS the standalone app now has no input bus at all, so it never records, JUCE opens its audio session for playback only, and the microphone permission (whose text still said "Zavalishin") is gone - tested on an iPad: it launches and plays without asking. Plugin hosts keep the input bus they've always seen.

v0.9.1: installers (macOS, Windows), iPad TestFlight, Factory/User presets

21 Oct 2026 · v0.9.1 · PR #169

  • Preset menu: open folders in place on touch

    On the iPad, a folder inside a folder's submenu couldn't be opened: juce::PopupMenu only opens a submenu on hover, and a touch has none. A tapped folder now shows its contents in the menu itself, with a back row on top. With a mouse, folders still open their submenu on hover.

  • iPad app: ship the factory presets inside the app

    With no installer on iPadOS, Presets/ is copied into the app bundle (juce_add_bundle_resources_directory) and PresetManager reads Factory/ straight from there - an optional separate factory directory, so paths stay Factory/... and the read-only rules are unchanged. Mac and Windows keep Factory/ next to User/.

  • iPad app: landscape only, TestFlight upload, icon

    The iPad app is locked to landscape (full screen, as iPadOS requires for that), targets iPadOS 13 (the oldest App Store Connect accepts), has an icon (Assets/AppIcon.png), a build number set per upload, dSYMs and the "no non-exempt encryption" declaration. installer/ios/upload-testflight.sh archives it in build-ios-appstore/ and uploads it to App Store Connect; App Store Connect needs the iOS 26 SDK (Xcode 26) or later.

  • Windows installer (Inno Setup), built by the Windows workflow

    installer/windows/Davai.iss installs the VST3 and the factory presets, for all users (Common Files\VST3, ProgramData) or only for the current user (%LOCALAPPDATA%\Programs\Common\VST3, %APPDATA%), making the shared User\ presets folder writable for everyone in the all-users case. The Windows workflow now builds Davai-<version>-Setup.exe after the VST3 and uploads it too. Unsigned for now. On Windows, Davai reads its presets from ProgramData when installed for all users, else from %APPDATA% as before.

  • macOS installer: signed, notarized .dmg holding a .pkg

    installer/macos/build-installer.sh builds the VST3 and AU as universal binaries in build-installer/ (new ZAVALISHIN_BUILD_AU option, off by default so everyday builds stay VST3-only), signs them with Developer ID, and packages them with the factory presets into one installer offering "just for me" / "all users" and a checkbox for each part. For all users, a postinstall script makes the shared User/ presets folder writable. The installer and the dist/Davai-<version>.dmg around it are notarized and stapled.

  • Add the Mael factory presets

    Presets/Factory/Mael (Atm, Bass, FX, Lead, Pad, Perc, Syn) - the source the macOS installer installs into Factory/.

  • Presets: read-only Factory/ and User/ folders

    The presets folder now holds Factory/ (installed by the installer, read-only: loadable, but never saved over, renamed, moved, deleted, locked, re-categorized or rated) and User/, where every preset saved from the plugin goes. Anything left at the top level from before moves into User/ on load. On macOS, Davai uses /Library/Audio/Presets/maelcore/Davai when installed for all users, otherwise the same path in ~/Library.

    The save dialog suggests a path relative to User/; the browser shows factory presets with the padlock, only offers Load for them, and moves and creates folders only inside User/.

v0.8.9: preset menu, browser and preset storage

21 Oct 2026 · v0.8.9 · PR #168

  • Preset browser: non-modal inside the editor, closes with the window

    While anything in JUCE is modal, keys it doesn't use are swallowed instead of reaching the host, so Ableton's computer MIDI keyboard couldn't play with the browser open. The browser is now a non-modal CallOutBox owned by TopBar and parented to the editor, closed on an outside click (global mouse listener), Escape, its button, or with the plugin window. Only its search box takes keyboard focus. The preset menu is also ended with the window, through its modal state rather than deleted.

  • Presets: move to ~/Library/Audio/Presets/maelcore/Davai on macOS

    JUCE's user application data directory is plain ~/Library on macOS, so presets sat in ~/Library/maelcore/Davai/Presets. They now live in the usual place for audio presets there; Windows and iOS keep their own. On first load, everything in the old folder is moved over (never overwriting an existing file) and the emptied old folders are removed.

  • Presets: save the displayed view and restore it on load

    The middle-row view, the envelope/LFO/FX/Sub-Noise/FM-Ring tabs and the Matrix pane are now written by createStateXml(), so a preset stores the view showing when it's saved and loading it brings that view back (a value missing from an older file leaves that part of the view as it is). An open editor notices the restore through a counter checked on its existing timer and switches right away. The DAW session uses the same path, which also makes it remember the Matrix pane now.

  • Locked presets: lock icon instead of greyed out, and not movable

    A locked preset was drawn greyed out, which read as disabled. It now uses the normal text colour with a padlock after its name. It can't be selected for Move selected, its Move to submenu is disabled, and PresetManager::movePreset() refuses a locked preset.

  • Preset browser: list each category once in the category filter

    Every preset's own categories were appended to the common list without removing repeats, so a category showed once per preset using it. Repeats are now removed (ignoring case), and the filter matches ignoring case.

  • Preset menu: open a folder's submenu on hover and close it on leaving

    The folder's juce::PopupMenu takes every mouse event while open, so the quick menu never saw the mouse move to another row and the submenu stayed until a click. The quick menu now polls the mouse while a submenu is open and closes it (opening the next folder's) as soon as another row is hovered. Folders open on hover only; a tap still opens one on touch.

Fix AU crash on closing the editor window

21 Oct 2026 · v0.8.8 · PR #167

  • Fix AU crash on closing the editor window

    Floating children (modulation ring overlays, knob value boxes, target grids) were added to getTopLevelComponent(). In the AU that's JUCE's own EditorCompHolder, whose destructor calls deleteAllChildren(): it deleted them before the editor, and then their real owners deleted them again (or, for member value boxes, freed memory they don't own) - a crash in ~LabeledKnob caught under lldb in Ableton.

    They now go to the enclosing plugin editor (floatingParentFor()), which never deletes its children, so each owner is the only one deleting them. Same area, so nothing moves; the VST3 behaves exactly as before.

v0.8.7: performance - modulation targets by position, not by name

20 Oct 2026 · v0.8.7 · PR #166

  • Audio: look up modulation targets by position, not by name

    modulate() took each target as a string and found it with a linear scan over every target name plus two name-keyed map searches, ~90 times a block; the Mod Envelope/Velocity loops did ~1000 more name searches per block. Profiling showed this was ~70% of the audio engine's idle CPU and ~35% while playing.

    Targets are now their position in LfoModulationTargets::ids, resolved at compile time for fixed ids and once in the constructor for per-LFO ones. ModEnvelopeMatrix gains indexed setters/apply like LfoModulationMatrix, and the Mod Envelope/Velocity routing parameters are fetched once. The modulation math itself is unchanged.

EQ: one band per side, shape selects the type; stable curve

3 Oct 2026 · PR #163

  • EQ curve: sample densely and include each band's centre frequency

    Sampling only on the pixel grid let a peak's top fall between points, so its drawn height moved as the peak slid. The curve now samples four points per pixel plus each band's centre, so every peak is drawn at its true height.

  • EQ: one band per side, with the shape choosing its type

    Each side of the EQ is a single band. The shape icons choose its type (shelf, notch/peak or pass) instead of the three filters adding up. Each band has FREQ, Q and GAIN; GAIN is hidden for the pass types. The defaults are 210 Hz (left) and 2014 Hz (right), Q 50% and gain 0 dB.

Oversample Transistor Ladder/Ring Mod/Saturation, report accurate latency, narrow FM/Ring bypass

1 Oct 2026 · v0.8.2 · PR #156

  • Switch to a component's own panel when it's turned on

    Enabling a bypassed component (LFO1/2/3, Sub/Noise, Reverb/FX Filter/Sat, Amp/Mod/Velocity envelope, Ring Mod) now also selects its tab, bringing the collapsible Envelope/LFO row into view too if it was hidden behind the Sequencer. Turning a component off does nothing here - the user stays wherever they are. Oscillator 1/2/Filter/Filter Envelope/Accent/Sequencer aren't included, since those live in the always-visible top row with no tab to switch to.

  • Oversample Ring Mod and Saturation; narrow FM/Ring bypass to Ring Mod only

    Ring Mod's osc1*osc2 multiply and Saturation's tanh() waveshaper are both classic aliasing sources, same mechanism as the filters' nonlinearities, with no protection before now. Each is only oversampled while actually enabled (gated on its own bypass toggle, not its knob values, to avoid the click/latency-instability risk discussed for Filter Mod/Filter FM). Ring Mod's multiply needs its own 2-channel Oversampling instance (channel 0/1 carry Osc 1/2's raw samples, not left/right); Saturation reuses the whole-buffer-at-once shape since its drive/mix are already fixed per-block values.

    Reported latency is now the sum of whichever oversampled stages are actually active (filter + Ring Mod + Saturation), recomputed via a new shared helper whenever any of the three changes.

    Also narrows the FM/Ring header's shared bypass lamp (user decision): it now only silences Ring Mod. Filter Mod/Filter FM have no bypass of their own any more - each knob being at 0 already means no effect, same as every other depth/amount knob in this plugin.

  • Silence AAX parameter-ID-length assertion in Debug builds

    Several LFO modulation matrix parameter IDs (e.g. "lfoEnabled_arpDistanceSemitones") exceed AAX's 31-character safe ID length once the LFO-index prefix is applied, tripping a jassert in Debug builds. Zavalishin is VST3-only and never ships AAX, so there's no truncation-collision to actually guard against - shortening the underlying parameter ID strings instead would break saved presets. Uses JUCE's own documented escape hatch for this situation.

  • Oversample the Transistor Ladder filter too

    Filter Mod/Filter FM modulate this filter's cutoff every sample with no anti-aliasing protection at all, unlike the Diode Ladder's own drive()/feedback nonlinearities. Always active while Transistor Ladder is selected, not gated on modulation depth - that would risk audible clicks and a constantly-changing reported latency every time a depth knob crosses zero during a performance.

    Shared the oversampling factor constant between both filter types (renamed diodeOversamplingFactor* to filterOversamplingFactor*) and extended latency reporting/DBG tracing to cover both.

  • Add debug logging for diode filter latency reporting

    DBG() traces confirming setLatencySamples() tracks the right value on prepareToPlay and on every Filter Type switch - compiled out entirely in Release builds, zero runtime cost outside Debug.

  • Report Diode Ladder's oversampling latency to the host

    getLatencyInSamples() from diodeOversampling was never passed to setLatencySamples(), so hosts had no way to compensate for the delay the diode filter's oversampling already introduces. Reported on prepareToPlay() and again whenever Filter Type switches, since only the Diode Ladder path is oversampled.

Filter drive, resonance compensation, and switch/MIDI glitch fixes (v0.6.0)

28 Aug 2026 · v0.6.0 · PR #95

  • Give Drive a true off point (0) and simplify the Transistor Ladder's mapping

    TB303DiodeFilter::drive() now allows driveAmount=0 as an exact identity (derived via L'Hopital: tanh(dx)/tanh(d) -> x as d->0, a removable singularity rather than a divergence) instead of clamping to a floor of 1 copied from juce::dsp::LadderFilter without checking whether it actually applied here - JUCE's own floor is a real necessity (its gain(drive) formula genuinely diverges as drive->0), ours wasn't.

    The shared Drive knob is now a raw, uncurved 0..1 position rather than a literal amount, since 0 needs to mean "off" for both filter types but they respond too differently to reach that via one shared curve. Three progressively more sophisticated curves were tried for the Transistor Ladder specifically (linear-in-gain, then two dB-linear designs against different reference signal levels) - each was verified numerically to do exactly what it was designed to do, and each still produced the same real-world result: almost no audible change until near the very top of the knob. Since that persisted across mutually-inconsistent designs, the curve design was abandoned for a plain linear map instead, which tested noticeably better. Separately (and unrelated to the mapping): the Transistor Ladder's drive has a hard ceiling the Diode Ladder's doesn't - JUCE's gain(drive) asymptotes to ~0.39, capping its total achievable loudness swing at a few dB, where the Diode Ladder's drive approaches a true limiter as it increases.

    All of this - including the abandoned attempts, not just the final approach - is written up in docs/DiodeLadderCalculations.md §5.3-§5.7.

  • Add a Drive knob and diode-ladder resonance compensation (issue #92)

    Drive: a single shared parameter hits juce::dsp::LadderFilter's own setDrive() for the Transistor Ladder, and a new drive() method for the Diode Ladder - a tanh waveshaper on the raw input, normalized by tanh(driveAmount) so it's exactly transparent at 0 and +/-1 for any drive amount. Kept outside the zero-delay feedback loop entirely, so none of the filter's existing closed-form math changes.

    The Drive range needed a skew toward 2.0: JUCE's own drive/gain formula is an empirical curve fit that flattens out past ~3-5, so an unskewed 1-10 range spent most of its travel doing nothing audible for the Transistor Ladder, while the Diode Ladder's own exact-normalization drive() keeps responding all the way to 10 - narrowing the range would have cut that off instead of fixing the real problem.

    Compensation: derived from scratch that every one-pole stage in the diode ladder has exactly unity DC gain relative to its own local input, then back-substituted through all four stages to get the whole filter's DC gain as exactly 1/(1+k) - the same simple form as the classic single-feedback Moog ladder despite the diode ladder's more complex local coupling. Since this is a lowpass, that DC/bass loss is also the perceived loudness loss as resonance increases - one exact compensation factor, (1+k), fixes both. New Comp button in the UI: a real toggle for the Diode Ladder (default on), always-on-but-disabled for the Transistor Ladder, since JUCE's own equivalent (a fixed comp constant) isn't exposed via any public API to toggle.

    Both chapters are written up in docs/DiodeLadderCalculations.md (§5, §6), including a direct comparison to JUCE's own (empirical, only approximate) versions of both mechanisms.

  • Stop MIDI channel-mode messages from being auto-learned as controller knobs

    Some DAWs send an All Notes Off (or Reset All Controllers/All Sound Off, CC 120-127) when transport stops. JUCE's MidiMessage::isController() doesn't exclude these from regular CCs, so handleMidiMessage() was handing them to MidiControllerMap, which auto-learns any unrecognized CC as the next knob in its fallback list and immediately applies its value - 0, for these messages - to that parameter. That's what was behind the "sound goes wrong after stopping playback" report: whatever parameter was next in line (often cutoff or decay) got silently forced to its minimum every time transport stopped.

  • Reset the target filter on Transistor/Diode Ladder switch (issue #93)

    Whichever filter type isn't selected never has processSample() called on it, so its internal state goes stale - feeding that stale, unrelated state into a filter right as it starts running again produced an audible glitch, worse and longer-lasting at high resonance. Detecting the switch on the audio thread each block and resetting the filter about to become active replaces that stale state with a known, clean one instead.

    Also bumps the project version to 0.6.0 for this batch (issues #92/#93).

Envelope, slide, accent, and square oscillator (v0.1.1 -> v0.2.0)

18 Aug 2026 · v0.2.0 · PR #15

  • Add square wave oscillator, closing out issue 13

    The TB-303's VCO is one oscillator core with a waveform switch, not two independent oscillators, so SawOscillator becomes Oscillator with a Waveform enum instead of gaining a parallel SquareOscillator class. Square wave reuses the existing PolyBLEP correction, applied at both of its edges (rising at phase 0, falling at phase 0.5) instead of the sawtooth's single wrap edge.

    Exposed via a new "Square Wave" APVTS bool and a WaveformSwitch control in OscillatorPanel: a rectangular two-icon switch (sawtooth left, square right) rather than the round bypass-style buttons used elsewhere, since this is a two-position selector rather than a bypass.

    docs/DESIGN.md gains an explanation of the oscillator's phase-based waveform generation and why PolyBLEP is needed at all.

  • Split accent into separate VCA and filter envelopes, add design doc

    The accent circuit's VCA boost and filter-cutoff sweep are driven by two physically distinct RC circuits on real hardware: the VCA path's attack is a fixed ~1.55ms (47k * 0.033uF), independent of any knob, while the filter path's attack is Resonance-coupled (2-147ms). A single shared accentEnvelope previously fed both paths, which incorrectly tied the VCA boost's timing to the Resonance knob.

    Also adds docs/DESIGN.md, explaining the TB-303's original design, the Devil Fish modification and its history, how Zavalishin's DSP maps back to the real circuitry, which parameter values are sourced versus estimated, and Devil Fish features not yet implemented.

  • Add accent as its own section with sourced envelope timing

    Splits accent into its own dedicated envelope (rather than reusing the filter envelope's already-decayed value) that sums two separate boost paths - VCA and filter cutoff - on top of the normal signal, gated by a new ACCENT panel with its own bypass switch. Also corrects amp envelope attack (3ms) and slide time constant (22ms, tau = 100k ohm * 0.22uF) to values sourced from the Devil Fish manual's circuit analysis, and confirms attack should stay linear rather than exponential on all three envelopes.

  • Add slide/glide between legato notes

    New PitchGlide: a one-pole exponential smoother (RC-lag style, coefficient = 1 - exp(-1/(tau*sampleRate))) chasing a target frequency, tau fixed at 12ms (~60-90ms felt glide time) to match the TB-303 - not knob-controlled, same as the envelope attack times.

    Since there's no sequencer here (just MIDI note on/off), legato - a new note-on arriving while the previous note is still held - is used as the slide trigger, the standard substitute when a per-step slide flag isn't available. A slide glides pitch and leaves both envelopes running untouched (no retrigger, gate logically stays high) rather than restarting them, matching the hardware - including the resulting quirk where a slide landing after the envelope's already decayed is heard as a quiet pitch-bent tail rather than a fresh pluck.

    processBlock now sets the oscillator's frequency every sample from the glide (previously once per block), with the TUNE knob's ratio applied as a separate live multiplier on top so it stays decoupled from slide timing.

    Closes #11.

  • Add amp/filter envelope, bypass buttons, and output panel stub

    Custom AttackDecayEnvelope (plain C++, single-pole RC-discharge-style exponential decay) instead of juce::ADSR, split into two independent instances matching the real TB-303's circuit: a fixed-shape VCA envelope (1ms attack, fixed 4s decay) and a VCF envelope (4ms attack, decay knob-controlled 200ms-2s) that sweeps the filter cutoff via a new ENV MOD amount. Neither responds to note-off - both always run their own decay to completion, matching the hardware.

    New EnvelopePanel (DECAY, ENV MOD, filter-env bypass) and OutputPanel (GAIN, amp-env bypass) sections - window grows to 4 equal panels. Bypassing either envelope falls back to simple pre-envelope behavior (static cutoff / hard note gate) without interrupting the other envelope's state, so re-enabling mid-note doesn't click. The output gain knob's parameter exists ahead of its DSP wiring (tracked in #14).

    Filter cutoff modulation needed per-sample resolution to sweep smoothly, so processBlock now runs the ladder filter one sample at a time (via 1-sample AudioBlocks) instead of one bulk call per block.

    Closes #10.
