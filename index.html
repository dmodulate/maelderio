Oscillo / JUCE 8 / C++20 / audio visualization

Audioviz

Audioviz is the oscilloscope and spectrum-analysis work from Oscillo: a real-time audio plugin and standalone app. The core waveform view uses a lock-aware circular buffer so the audio thread can keep writing samples while the UI takes coherent snapshots for drawing.

For interface images, the cleanest route is to run the standalone app, capture the waveform and spectrum modes with macOS screenshots, then crop them into assets/apps/audioviz-waveform.png and assets/apps/audioviz-spectrum.png.

Audioviz interface image 
void ScopeWaveformHistory::pushSamples(
    const juce::AudioBuffer<float>& buffer,
    int numInputChannels)
{
    readWriteStatus.fetch_add(1, std::memory_order_acq_rel);
    auto writePosition = scopeWritePosition.load(std::memory_order_relaxed);

    for (auto sample = 0; sample < buffer.getNumSamples(); ++sample)
    {
        for (auto channel = 0; channel < channelsToStore; ++channel)
        {
            const auto storageIndex = channel * scopeSize + writePosition;
            scopeSamples[storageIndex].store(
                buffer.getSample(channel, sample),
                std::memory_order_relaxed);
        }

        writePosition = (writePosition + 1) % scopeSize;
    }

    scopeWritePosition.store(writePosition, std::memory_order_release);
    readWriteStatus.fetch_add(1, std::memory_order_release);
}

The samples are stored in per-channel rings. The UI checks the read/write status before and after copying; if the audio thread writes during the copy, the UI discards that snapshot and tries again.

Music Visualizer

Music Visualizer is a real-time audio-reactive visual engine. Python extracts deterministic audio features from live input, maps them to visual parameters, then sends those parameters to GLSL shaders.

Good images here would be stills from the particle and fluid shader presets, plus a short screen recording exported as a poster frame.

Shader still image 
def compute_kick(signal, sample_rate):
    split = signal.size // 2
    previous_bass = compute_frequency_bands(
        signal[:split], sample_rate)["bass"]
    current_bass = compute_frequency_bands(
        signal[split:], sample_rate)["bass"]

    growth = max(0.0, current_bass - previous_bass)
    kick = current_bass * 0.65 + growth * 0.35
    return float(np.clip(kick, 0.0, 1.0))

This feature estimates a kick by combining current bass energy with low-frequency growth between the first and second half of the audio window.

Zavalishin / JUCE 8 / C++20 / acid synthesizer

303 Synth

A 303 emulation is not just a saw oscillator through a generic low-pass filter. The signature comes from the interaction of slide/accent behavior, a bright saw/square oscillator, envelope-shaped cutoff, and the resonant diode-ladder low-pass filter.

This project models the filter as a topology-preserving transform diode ladder. Resonance is solved inside the same sample with Newton iterations, avoiding an extra feedback delay and keeping the resonant peak closer to the intended cutoff.

303 synth interface image 
float u4Estimate = s4;

for (auto iteration = 0; iteration < 4; ++iteration)
{
    const float drive = compensatedInput - k * u4Estimate;
    const float saturated = std::tanh(drive);
    const float f = a4 * saturated
        + statesContribution - u4Estimate;
    const float fDerivative =
        a4 * (-k * (1.0f - saturated * saturated)) - 1.0f;
    u4Estimate -= f / fDerivative;
}

The filter is specific because the resonance feedback is implicit: the current sample's output depends on itself. Solving that loop gives the nonlinear diode saturation and resonance their 303-like bite.

Klide / JUCE 7 / C++17 / older project

Klide

Klide is an older Euclidean rhythm drum-machine VST3. It can run four sample sequences and distribute pulses across a fixed number of steps with the Bjorklund algorithm. It is a meaningful early project, but it needs refactoring: clearer naming, modern JUCE/CMake structure, tests, and separation between sequencing, audio, and UI state.

Klide interface image 
do {
    count_[level] = divisor / remainder_[level];
    remainder_[level + 1] = divisor % remainder_[level];
    divisor = remainder_[level];
    level = level + 1;
} while (remainder_[level] > 1);

count_[level] = divisor;
build_string(level, reverse);

Bjorklund's algorithm repeatedly divides rests by pulses to create the most even distribution possible. For example, 5 pulses over 16 steps becomes a rhythm where the gaps are balanced rather than clustered.
